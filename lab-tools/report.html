Prefill Attention Port

The long-prompt attention lab work as production PRs. RTX PRO 6000 Blackwell (sm_120). Updated 2026-11-02.

On 6016 queries over 8192 keys, the stack takes the cube fragment routine from 2060 µs (the best setting dev lists) to 1495 µs (−27%). FlashInfer takes 1560 µs on the same box today. Six cubek PRs and two cubecl PRs, all into dev/louisfd; the seventh, a cubecl pin bump, was closed once dev pinned past #2019 by itself. cubecl#2019 merged at 13:58 today, so nothing waits on it, and no PR carries Merge after: cubecl#2019.

Dropped, kept per shape, and why

  • Stage alignment floor: nothing to port. #2012 is merged and comes in with the pin. Alone it was within noise in the lab ablation here (1890 vs 1902 µs); the wide blocks it was waiting for are #1059.
  • Fused unbiased step: kept, per shape. On for three listed shapes (−1.2 to −2.3%; −0.7% more on top of async Q), off where it cost (+2–3% on f1x8 swizzled). Alone, before the inner fills stop spilling, it only cost.
  • Async Q: kept, per shape. On for the two copy-engine shapes (−1.1%, −1.2%), off where it cost (+1–4% on f1x4). It does nothing when the units copy the K/V.
  • Unchecked inner fills: kept. −16% on the register-bound f2x4, within noise elsewhere. It needs a small cubecl API (#2029); Stages::fill_inside from the lab wasn’t needed, because the ring already had the unchecked path.
  • Not ported, not in the spec: SPLIT_KV, FILLERS, EARLY_K, LOCAL_SUMS, CUBES, the output bounce (the lab marked it wrong), and the timing-only switches (NO_SOFTMAX, NO_RESCALE, NO_PARTIAL, NO_MERGE, SKEW, PINGPONG). The lab’s best config uses none of them.

Correctness

  • Every timed setting matches the dev reference to 3.05e-5 (one f16 ulp). The references come from unmodified dev (793240eb) and were checked against an f64 CPU computation on sampled rows: within 3e-4 at 2048 and 1.6e-5 at 6016×8192, i.e. f16 rounding.
  • every_cube_staged_setting_matches_the_host_at_a_head_dim_of_128 (cubek-attention-backward, CUDA, the combined branch) passes, and none of the listed settings printed “declined on this device”. That test counts a decline as a pass, so I checked the log for it. The full cubek-attention-backward suite on the merged stack: 34/34 pass. Its 54 decline lines all come from backward-pass kernels this stack doesn’t touch (this device lacks the cmma instruction they need).
  • cubek-attention lib 52/52 and cubek-microkernel lib 28/28 on each PR branch; clippy and rustdoc clean for the new code.
  • cubecl#2029: the new test lets its last block run into NaN keys. A planted skip of the unchecked fill makes it fail, so it does exercise the path. The 8×8×8 softmax cases print Skipped on this GPU and count as passes; the 16×16×16 ones run.

Found along the way

  • The log’s 1460 µs needs K/V on the copy engine. Its best env omits CUBEK_LAB_KV_DELIVERY=async, and without it the lab takes 1852 µs here. FlashInfer measures 1560 µs today against the log’s 1552, so the box itself is unchanged.
  • #2019 broke wgpu. WGSL has no infinity literal, and the backend printed f32(+Inf). Fixed in cubecl#2028. The f16 case can’t run here, because this Vulkan adapter has no shader-f16.
  • The harness’s saved output is [queries, heads, dim], not [heads, queries, dim]. That matters for any outside check.
  • Shared GPU. Another session benchmarks on this GPU, and the container’s nvidia-smi doesn’t show its processes. We agreed to time only under flock /tmp/gpu-timing.lock.
  • Clocks. nvidia-smi -lgc 2100,2100 reports success, but I read 2317–2332 MHz afterwards, so I couldn’t confirm the lock holds. FlashInfer matching the log suggests the conditions are comparable.
  • cargo build -p cubek-microkernel alone skips the attention module (feature attention), so build through cubek-attention to check it.
