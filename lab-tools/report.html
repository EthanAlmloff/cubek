Prefill Attention Port

Morning report. The long-prompt attention lab work, turned into production PRs. RTX PRO 6000 Blackwell (sm_120). Last updated 2026-11-02, late evening.

In short: the lab’s speed-ups are now clean code in six cubek PRs and one cubecl PR. None of them uses env switches. On the headline problem (6016 queries over 8192 keys) the autotune’s best goes from 1966 µs on dev to 1493 µs (−24%), faster than FlashInfer (1561 µs). The gain is 17–24% at every size I tried. Everything is pushed and mergeable. Nothing is merged; that is your call.

Decisions I made for you, and why

  • Nothing pins #2019 or says “Merge after: cubecl#2019”. #2019 merged at 13:58, before any PR needed it.
  • One PR per measured change, and two stacked. Wide blocks, inner fills, last-first and the eight-warp shapes each stand alone. Unbiased steps and the async query stack on the eight-warp PR, because they flip flags on its rows.
  • Unbiased steps and the async query are per shape, never defaults. Each one costs some shapes 1–4%.
  • Inner fills needed a cubecl API (#2029). The lab’s Stages::fill_inside wasn’t needed: the ring already had an unchecked path, and the walk just never said it was a run.
  • #1060 carries a special cubecl pin (dev’s pin + #2029) until #2029 merges. Each time dev moved its pin, I merged the new pin into the cubecl branch and re-pinned.
  • Not ported: lab switches outside the spec (SPLIT_KV, FILLERS, EARLY_K, LOCAL_SUMS, CUBES, the output bounce, timing-only switches). The lab’s best config uses none of them.
  • All headline numbers were re-measured late. Another session ran unlocked GPU jobs in the afternoon, so I threw away every number taken between 15:50 and 19:40.
  • cubek#1070 and cubecl#2033 are not mine. I left them to the orchestrator, who handled #1070.
  • Killed my own debug-build test run, because it held the GPU lock while only compiling. Re-ran it in release: 34/34.

What’s left, or didn’t work

  • Small problems still trail FlashInfer: 2048² by 18%, 512 × 8192 by 13%, 4096² by 4%. 16384² is within 1%. At these sizes launch overhead weighs more; see the ncu line above.
  • The lab is still ~2% faster than the stack at 6016 × 8192 (1466 vs 1493 µs). The lab’s cubecl carries the open ldmatrix-pairs PR cubecl#1992, which production doesn’t have. That is the likely gap.
  • A mistake: a scripted dev merge pushed conflict markers to #1061–#1064 for a few minutes. I fixed it with follow-up commits; force-push was blocked, as it should be. So those branches have a messy merge commit in their history. A squash merge hides it.
  • The 8×8×8 softmax tests print Skipped on this GPU and count as passes. The 16×16×16 ones run.

Correctness

  • Every timed setting matches a reference from unmodified dev to 3.05e-5 at 6016 × 8192 (one f16 ulp), and to 2.4e-4 on the square sizes, the same as dev against itself. The references were checked against an f64 CPU computation on sampled rows.
  • The cubek-attention-backward suite on CUDA, merged stack: 34/34. It includes the forward check of every listed cube setting. That test counts a decline as a pass, so I read the log: the only declines come from backward kernels this work doesn’t touch.
  • Lib tests on each branch: cubek-attention 52/52, cubek-microkernel 30/30.

Found along the way

  • #2019 broke wgpu. WGSL has no infinity literal. Fixed in cubecl#2028.
  • The harness saves output as [queries, heads, dim], not [heads, queries, dim].
  • Shared GPU. The container’s nvidia-smi doesn’t always show the other session’s processes. Both sessions now time only under flock /tmp/gpu-timing.lock, and my scripts redo any run that overlaps another GPU process.
  • cargo build -p cubek-microkernel alone skips the attention module (feature attention), so build through cubek-attention.
  • ncu needs sudo on this box (RmProfilingAdminOnly=1).
